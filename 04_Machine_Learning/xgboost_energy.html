2. Forecasting Horizon Explained

The forecast horizon is the length of time into the future for which forecasts are to be prepared. These generally vary from short-term forecasting horizons (less than three months) to long-term horizons (more than two years).

def create_features(df):
    """
    Create time series features based on time series index.
    """
    df = df.copy()
    df['hour'] = df.index.hour
    df['dayofweek'] = df.index.dayofweek
    df['quarter'] = df.index.quarter
    df['month'] = df.index.month
    df['year'] = df.index.year
    df['dayofyear'] = df.index.dayofyear
    df['dayofmonth'] = df.index.day
    df['weekofyear'] = df.index.isocalendar().week
    return df

df = create_features(df)

3. Lag Features

  • What was the target (x) days in the past.
def add_lags(df):
    target_map = df['PJME_MW'].to_dict()
    df['lag1'] = (df.index - pd.Timedelta('364 days')).map(target_map)
    df['lag2'] = (df.index - pd.Timedelta('728 days')).map(target_map)
    df['lag3'] = (df.index - pd.Timedelta('1092 days')).map(target_map)
    return df
df = add_lags(df)

On this site’s backtest

The tutorial above uses the PJM East dataset and its cells do not run here. This section runs XGBoost on the household series with the backtest every other model uses, and with the feature set that scored best on the Feature Engineering page (seasonal lags, calendar, Fourier terms and rolling statistics, all known 24 hours ahead), imported from ML_Timeseries.features. The model trains once on everything before the first test origin.

import numpy as np
import pandas as pd
import xgboost as xgb

from ML_Timeseries.backtest import backtest, future_index, origins, record, score
from ML_Timeseries.data import load_household
from ML_Timeseries.features import make_features
hh = load_household()
y, FILLED = hh["kwh"], hh["filled"]
train = y.iloc[:origins(y.index)[0]]
model = xgb.XGBRegressor(n_estimators=600, learning_rate=0.03, max_depth=6, subsample=0.8, colsample_bytree=0.8,
                         tree_method="hist", n_jobs=1, random_state=0)
model.fit(make_features(train).iloc[700:], train.iloc[700:])


def xgb_forecaster(history, horizon):
    ext = pd.concat([history.iloc[-800:], pd.Series(np.nan, index=future_index(history, horizon))])
    return model.predict(make_features(ext).iloc[-horizon:])


xgb_score = score(backtest(y, xgb_forecaster), y, exclude=FILLED)
_ = record("XGBoost, engineered features", "machine learning", xgb_score, notebook="04_Machine_Learning/05_XGBoost_Energy")
print(f"XGBoost: MASE {xgb_score['mase']:.3f}, skill {xgb_score['skill']:+.1%}")
XGBoost: MASE 0.663, skill +17.5%

XGBoost lands within half a point of scikit-learn’s histogram gradient boosting on the same features (both about +17% skill against seasonal naive). The two libraries implement the same idea, boosted regression trees on binned features, and on a table of a few dozen columns their differences in regularisation and tree growth barely register. The Feature Engineering ablation showed where the gains come from: the features, and above all the calendar. Choose between XGBoost, LightGBM and scikit-learn on speed, deployment and API, not on expected accuracy.
